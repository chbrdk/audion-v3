# UI locale (en / de)

**Spec:** `specs/domain/settings.md` SET-L1 (+ Wave-2/3 surface coverage)  
**Paths:** `paths.localeStorageKey` · `paths.i18nLibPath` · `paths.localesDir`

## Model

Checkion/Brandion/Plexon-style nested JSON + `createTranslator` — no next-intl.

| Piece | Path |
|-------|------|
| Dictionaries | `apps/web/locales/en.json` · `de.json` |
| Helper | `apps/web/lib/i18n.ts` |
| Hook | `useUserPrefs().t` / `useT()` (same prefs as theme/locale) |

`setLocale` writes localStorage and `lang`; React re-renders chrome with the matching dictionary.

Server hub pages pass `titleKey` / `descriptionKey` into `AppShell` so the client shell resolves strings after hydration. List/detail panels that need `t()` are `'use client'`.

## Namespaces

**SET-L1:** `common` · `nav` · `pages` · `settings` · `login` · `home` · `hubs` · `status` · `admin`

**Wave 2:** `lists` · `tiles` · `dialogs` · `chat` · `setup` · `queue` · `detail` · `wave` · `flows`

**Wave 3:** `prompts` · `chatExtra` · `personaEdit` · `phases` · `knowledge` · `apiDocs` · `inspector` · `tavus`

## Out of scope

- Persona/TG **content** mirrors (`profileDe`) and AI `output_locale`
- Dynamic backend/API error passthrough strings
- URL locale segments / next-intl
- Rare dim-hints / mock-context microcopy without stable keys
